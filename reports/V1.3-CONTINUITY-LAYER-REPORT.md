This phase adds a **Continuity Layer**: it compresses "current engineering
state" + "current work semantics" into a portable, resumable agent checkpoint so
a new session does not depend on the previous session's context. It reuses the
existing technology-agnostic core (`core/aegl.py`, `bin/aegl`) and does not
redesign the governance or adapter layers.

Design baseline: `AEGL-v1.3-Continuity-Layer-Build-Plan.md` (committed to this
branch). Scope was held to the plan's MVP §24 — no Beads integration, no
Java/Python/TypeScript adapter, no RAG / vector DB / multi-agent scheduler.

## 1. Architecture

```text
Repository reality (Git / HEAD / VERSION / CI)     Agent semantics
                 │                                        │
        collector.py (deterministic)              work.json / CLI flags
                 └───────────────┬────────────────────────┘
                                 ▼
                            state.json                 ← canonical machine truth
                                 │
                 ┌───────────────┼────────────────┐
                 ▼               ▼                ▼
            HANDOFF.md     NEXT-SESSION.md   history/<id>.{json,md}
             (warm)            (hot)              (cold)
                 │
                 ▼
             aegl resume  →  lightweight consistency check (never a gate)
```

- **state.json** is the canonical machine-readable truth.
- **HANDOFF.md / NEXT-SESSION.md** are projections, not canonical storage.
- **resume** compares only branch / HEAD / working tree / version; CI is shown
  but is never a hard gate; STALE is a warning, not a block.

## 2. Modules (`core/continuity/`)

| Module | Responsibility |
|--------|----------------|
| `collector.py` | Deterministic facts: Git branch/HEAD/dirty/remote, VERSION, tags, latest commit, best-effort CI (`gh run list`, timeout, graceful degradation). |
| `state.py` | Schema version, atomic `write temp → fsync → rename`, read/write, config, structural `validate_state`. |
| `renderer.py` | `state.json` → `HANDOFF.md` + `NEXT-SESSION.md`. |
| `resume.py` | Snapshot vs. current comparison + resume brief. |
| `history.py` | Immutable snapshot save/list/prune. |
| `events.py` | Append-only JSONL of phase-level events. |
| `secrets.py` | Best-effort secret redaction + `$HOME` path normalisation. |
| `memory.py` | Reserved `PersistentMemoryBackend` (only `none` in v1.3). |
| `commands.py` | Command orchestration. |
| `state.schema.json` | Documented JSON schema for `state.json`. |

`core/aegl.py` gained handlers `cmd_status` / `cmd_handoff` / `cmd_resume` /
`cmd_continuity`; no existing command changed.

## 3. CLI

```bash

              [--next ...] [--next-command ...] [--do-not-repeat ...] [--json]

aegl continuity check   [--root R] [--json]   # diagnostic, never a gate
```

`--root` defaults to the AEGL repo root; the whole layer is root-relative, which
is what makes the fixtures isolated.

## 4. Runtime layout

```text
.aegl/continuity/
├── state.json
├── HANDOFF.md
├── NEXT-SESSION.md
├── events.jsonl
├── config.json
└── history/<YYYYMMDDTHHMMSSZ>.{json,md}
```

`config.json` defaults:

```json
{ "historyLimit": 20, "commitCurrentState": true, "commitHistory": false,
  "includeCi": true, "redactSecrets": true, "memoryBackend": "none" }
```

**Git hygiene (deviation from plan §37, on purpose).** The plan *suggests*
committing `state.json` / `HANDOFF.md`. That is incompatible with a deterministic
`aegl resume` — committing the handoff changes `HEAD`, which would make every
committed handoff instantly STALE. The runtime directory `.aegl/continuity/` is
therefore **gitignored** (consistent with the repo's existing "AEGL runtime
overlay" philosophy), so `resume` stays meaningful and handoff output adds no
Git noise. Schema/templates are committed in code instead.

## 5. Machine vs. semantic facts

- **Machine (program-collected):** branch, HEAD, dirty, remote, VERSION, tags,
  latest commit, CI status/runId.
- **Semantic (agent-provided):** `goal`, `currentTask`, `completed`,
  `inProgress`, `blocked`, `failedApproaches`, `importantDecisions`,
  `doNotRepeat`, `knownRisks`, `openQuestions`, `next`. Supplied via CLI flags
  or `.aegl/continuity/work.json`; merged over the previous snapshot.

## 6. Events (`events.jsonl`)

Append-only, phase-level only — **not** every shell command, no event-sourcing
platform. Types: `phase_started`, `phase_completed`, `task_started`,
`task_completed`, `decision`, `blocked`, `unblocked`, `handoff_created`,
`resume_started`, `resume_completed`. Values are redacted before writing.

## 7. Security / redaction

Best-effort redaction (not a DLP platform) of credential-bearing text before
anything is persisted:

- `*_TOKEN` / `*_KEY` / `*_SECRET` / `PASSWORD` / `PASSWD` = value
- `Authorization: <scheme> <credential>`, standalone `Bearer <token>`
- provider tokens (`ghp_*`, `github_pat_*`, `sk-*`, `AKIA*`, `xox*`)
- PEM private-key blocks
- non-essential home paths normalised to `$HOME/...`

## 13. Known limitations

- CI status is best-effort: requires `gh`; otherwise `unavailable`, and in tests
  `skipped`. It is informational, never a resume gate.
- `repository.head` is stored as the short SHA.
- `resume` reports STALE on branch/HEAD/version change and a WARNING only for a
  dirty tree; it never blocks a new session (by design).
- `history/` and `events.jsonl` are local runtime artifacts (gitignored); they
  are not committed. There is no time-travel / rollback.
- `PersistentMemoryBackend` is reserved; only the `none` backend exists. Beads is
  deferred to v1.4.
- No agent hooks (Claude/Codex/Cursor) are wired yet — handoff is manual
  (`aegl handoff`), which is the plan's v1.3 stance.
- Android `verify` was not run locally (no Android SDK on this host); it is
  covered by the `android-adapter-smoke` CI job.
