This phase adds an **OPTIONAL** persistent work-memory / long-horizon work-graph
backend driven through the official Beads `bd` CLI. It follows the architecture

Continuity contract.

---

## 1. Architecture

```text
AEGL Continuity  ──owns──▶ session continuity (branch/HEAD/CI/handoff/resume/history)
     │
     └── reads (reference only) ──▶ PersistentMemoryBackend = beads
                                         │  (core/continuity/backends/beads.py)
                                         └── subprocess ──▶ bd CLI
                                                              │
                                                    Beads/Dolt  at
                                                    BEADS_DIR=<root>/.aegl/beads
RuleSync  ──owns──▶ agent rules (AGENTS.md / CLAUDE.md / Cursor rules)
```

- **AEGL owns session continuity. Beads owns the long-horizon work graph.
  RuleSync owns agent rules.** No canonical data is duplicated.
- Integration is **CLI-only** (`bd` subprocess). AEGL never opens the Dolt DB,
  never imports the Go module, never re-implements the dependency DAG or the
  ready queue.

## 2. Backend boundary

`core/continuity/memory.py` stays the thin registry; all Beads specifics live in
`core/continuity/backends/beads.py` (`BeadsRunner` + `BeadsMemoryBackend`).
`memory_commands.py` holds only CLI orchestration.

The narrow contract exposed to Continuity:

| Method | Purpose |
|--------|---------|
| `available()` | `bd` present **and** version inside the supported window |
| `version()` / `supported()` | parsed `bd --version`; 1.3.x window |
| `initialized()` | `$BEADS_DIR/config.yaml` (or `metadata.json`) exists |
| `setup()` | `bd init --stealth` at `BEADS_DIR` (parent pre-created) |
| `health()` / `summary()` | `bd status --json` snapshot |
| `ready_summary(limit)` | `bd ready --json --limit N` (Beads decides the result) |
| `current_work()` | `bd list --json --status in_progress` |
| `memories()` / `prime()` | `bd memories --json` / `bd prime [--memories-only]` |
| `remember()/forget()` | `bd remember` / `bd forget` (redaction enforced) |
| `reference_summary()` | the `state.json` `memory` block (reference only) |

`store()` (the v1.3 handoff hook) is deliberately a **no-op**: a handoff never
auto-creates Beads issues or copies the graph. `load_backend` is a registry;
unknown backend names fall back to `none`.

Lifecycle commands (`create`, `dep add`, `update --claim`, `close`, `show`) are
**not** wrapped — the agent uses them directly via `aegl bd ...`.

## 3. CLI

```bash
aegl memory status [--json]                 # availability / version / health
aegl memory setup beads                     # stealth init + config
aegl memory prime [--memories-only] [--json]
aegl memory remember [KEY] VALUE [--key K] [--value V]
aegl memory ready [--limit N] [--json]      # thin wrapper over bd ready
aegl memory disable                         # backend -> none, data preserved
aegl bd <bd args...>                        # environment-correct passthrough
aegl resume --with-memory                   # bounded memory summary (opt-in)
```

`aegl resume` stays Continuity-only by default; memory is opt-in via
`--with-memory` or config `includeMemoryOnResume`. The memory brief is bounded
(backend / version / ready count / current task) — the full `bd prime`
(~826 words) is **never** concatenated into resume.

## 5. Storage location

- `BEADS_DIR=<root>/.aegl/beads` (pointed at the `.beads` dir itself).
- AEGL pre-creates `<root>/.aegl/` **before** `bd init` — the workspace gate
  requires the parent of `BEADS_DIR` to exist (verified in the sandbox).
- The Dolt runtime data, gate lock and caches are **gitignored**
  (`.aegl/beads/`, `.aegl/beads.gate.lock`, `.aegl/*.gate.lock*`). `setup` also
  appends the same patterns to `.git/info/exclude` (git-internal, stealth) so a
  target project's tracked files are untouched.

## 6. Telemetry policy

AEGL's default privacy stance: **telemetry disabled** on every `bd` invocation
it controls, via `BD_DISABLE_METRICS=1`, `DO_NOT_TRACK=1`, plus
`BD_NON_INTERACTIVE=1` and `NO_COLOR=1`. `aegl memory status` reports
`Telemetry: disabled`. Setup never enables telemetry.

## 7. Stealth / RuleSync conflict prevention

- Setup runs **`bd init --stealth`** only. It writes nothing to AGENTS.md,
  CLAUDE.md, `.claude/`, `.codex/`, `.cursor/` or `.agents/`; installs no git
  hooks; changes no `core.hooksPath`; creates no commit.
- AEGL **never** runs `bd setup <agent>`.
- RuleSync remains the single source of truth. The generator
  (`bridge/linux/40-render-governance.sh`, `scripts/40-render-governance.ps1`)
  now emits one short **"Persistent Work Memory (optional)"** guidance block;
  the committed projection `fixture/.rulesync/rules/00-governance.md` was
  regenerated from `governance/policy.json` (only that file changed).

## 8. Source-of-truth ownership

- `state.json` stores only a **reference** block:
  `{backend, available, supported, initialized, beadsVersion, dataDir,
    readyCount, currentTask, checkedAt}`.
- It is **never** a copy of the work graph — asserted in the smoke test (the
  block's key set is restricted to the allowed reference fields).
- Beads is the sole authority for task status; AEGL is the sole authority for
  session state. There is no round-trip (Beads DB → AEGL JSON → Handoff → Beads).

## 9. Secret handling

`aegl memory remember` runs every value (and key) through
`core/continuity/secrets.py` **before** reaching `bd`. A hit on any credential
pattern is **rejected outright** — nothing is written, the secret is never
echoed, and a defence-in-depth check inside `BeadsMemoryBackend.remember`
refuses again. Beads performs no redaction of its own.

## 10. Failure fallback (tested)

| Failure | Behaviour |
|---------|-----------|
| `bd` missing | backend unavailable → warning; `setup` prints install guidance |
| unsupported version | `available=false`, `setup` refuses; Continuity unaffected |
| not initialized | reads degrade to warnings; handoff/resume still work |
| timeout | bounded by subprocess timeout (probe 3s); no long stalls |
| invalid JSON | parsed defensively → counts `(n/a)`, no crash |
| broken/unreachable bd | handoff/resume/status continue normally |

Every failure is downgraded to a **WARNING**, never a Continuity FAIL.

## 16. Known limitations

- Beads is **not** installed by AEGL; without it, long-horizon tasks/memory are
  simply absent (Continuity is unaffected). AEGL never auto-downloads Beads.
- Compatibility is deliberately narrow (1.3.x). A future Beads minor will show
  as unsupported until AEGL re-verifies it — by design, because the memory model
  is under active upstream redesign.
- The `bd` binary is large (~154 MB) and embedded Dolt startup dominates cold
  calls; AEGL applies short timeouts and never calls `bd` when disabled.
- `bd doctor` is not usable in embedded mode; health relies on `bd status`.
- Cross-machine sync (`bd dolt push/pull`) is left to the user; AEGL does not
  proxy it and does not auto-configure a remote.
- No `purge` command in v1.4: `disable` never deletes data; removing
  `.aegl/beads/` manually loses the graph unless a remote/export exists.
- `currentTask` is the first `in_progress` issue; multi-agent claim semantics
  are Beads' (--claim), not AEGL's.
