This phase turns the governance *experiment* into a governance *platform*: a
technology-agnostic core plus per-technology adapters that can `inspect`,
`attach`, `verify` and `detach` a **named** target project. It never scans a
parent directory and never copies this repository's `upstream/` into a target.

## Adapter architecture (Core + Adapters)

- `core/aegl.py` — technology-agnostic CLI (argparse), adapter discovery, dispatch.
- `bin/aegl` — entry point (`exec python3 core/aegl.py "$@"`).
- `adapters/<lang>/adapter.json` — descriptor (language, build system, detection
  markers, capabilities, `implemented` flag).
- `adapters/<lang>/adapter.py` — implementation, loaded only when `implemented`.

| Adapter      | Implemented | Notes |
|--------------|-------------|-------|
| `kotlin`     | yes         | Gradle + Kotlin: detekt + Konsist architecture test |
| `android`    | descriptor  | not implemented in v1.1 |
| `java`       | descriptor  | not implemented in v1.1 |
| `python`     | descriptor  | not implemented in v1.1 |
| `typescript` | descriptor  | not implemented in v1.1 |

Descriptor-only adapters report `implemented: false`; `attach`/`verify` refuse
them rather than pretending support.

## CLI commands

```
aegl adapters                     # list adapter descriptors
aegl inspect <project> [--write]  # read-only scan -> project profile
aegl attach  <project> [--dry-run]
aegl verify  <project>            # run the adapter governance gate
aegl detach  <project> [--dry-run]
```

`inspect` is read-only by default (profile to stdout); `--write` optionally
writes `<project>/.aegl/project-profile.json`.

## Target descriptor schema

`targets/example-target.yaml` documents the declarative form:

```yaml
project:    { name, path }
technology: { language, buildSystem, framework }
governance: { specKit, architectureGuard, ruleSync, architectureTests, staticAnalysis }
qualityGate:{ architecture, staticAnalysis, unitTests, build }
```

The CLI detects the same facts from the filesystem; the descriptor lets a user
pin them.

## Kotlin adapter — injection model (non-invasive)

`attach` writes an AEGL overlay and **never edits the target's build files**:

```
<project>/.aegl/policy.json
<project>/.aegl/governance/constitution.md
<project>/.aegl/governance/architecture_constitution.md
<project>/.aegl/detekt.yml
<project>/.aegl/kotlin/GeneratedArchitectureTest.kt   # Konsist architecture test
<project>/.aegl/aegl-init.gradle                      # Gradle init script (detekt + Konsist)
<project>/.aegl/quality-gate.sh                       # gate bridge
<project>/.github/workflows/aegl-governance.yml       # CI bridge
```

`verify` runs `./.aegl/quality-gate.sh`, i.e.
`gradle --init-script .aegl/aegl-init.gradle aeglQualityGate`, where the init
script adds detekt + Konsist + the generated test source dir at run time. This
keeps `modified = []` for a normal project, which is what makes `detach` safe.

Note: the generated test uses `Konsist.scopeFromDirectory("src/main/kotlin")`
rather than `scopeFromProduction()`; the latter derives source sets from paths
and is confused by the injected `.aegl/kotlin` test source dir.

## Manifest design

`.aegl/manifest.json` records everything needed for `detach`/upgrades:

```json
{
  "aeglVersion": "1.1.0-dev",
  "adapter": { "id": "kotlin", "version": "1.1.0-dev" },
  "targetPath": "...",
  "created":  [ { "path": ".aegl/...", "sha256": "..." } ],
  "modified": [ { "path": "...", "beforeSha256": "...", "afterSha256": "...", "backup": "..." } ],
  "preserved":[ "build.gradle.kts", "settings.gradle.kts" ],
  "policy": ".aegl/policy.json",
  "qualityGate": ".aegl/quality-gate.sh"
}
```

`detach` deletes only files in `created` whose hash still matches, restores
`modified` files from backups, and never deletes `preserved`/user files.

## Dry-run behaviour

`attach --dry-run` prints `wouldCreate / wouldModify / wouldPreserve / wouldRun`
and writes nothing. `detach --dry-run` prints what it would remove/restore and
writes nothing (the plan is computed before any mutation).

## Known limitations

- Only the **kotlin** adapter is implemented; other technologies are descriptors
  and are not claimed as supported.
- The Kotlin adapter assumes a single-module Gradle build rooted at the target
  path (`src/main/kotlin`).
- The adapter injects detekt/Konsist via an init script; if the target already
  configures those tools, integration is not yet merged.
- Runtime `verify` downloads the detekt plugin and Konsist from Maven Central.
- `scopeFromDirectory("src/main/kotlin")` is single-module only.
