This phase adds an **Android target adapter** to the existing technology-agnostic
core + technology-adapter platform. It does **not** redesign the core and does
**not** copy another inspect/attach/verify/detach: the Android adapter plugs into
the same contract (`detect` / `inspect_summary` / `attach` / `verify` / `detach`
/ `describe`) and reuse `core/aegl.py`, `bin/aegl`, the `.aegl` overlay, the
manifest, hash-safe detach and the CI infrastructure.

## 1. Android detection (`aegl inspect`)

`detect()` matches when a project has `settings.gradle(.kts)` **and** an Android
Gradle plugin (`com.android.application` or `com.android.library`) in any Gradle
build file. The Kotlin adapter was hardened to never claim Android projects
(`... and not androidPlugin`), and the core's detection priority is
`["android", "kotlin"]`.

Indicators produced: `settingsGradle`, `buildGradle`, `gradleWrapper`,
`androidApplication`, `androidLibrary`, `androidPlugin`, `kotlinPlugin`,
`existingDetekt`, `existingKonsist`, `existingCI`, `existingClaude`,
`existingAgents`, `existingArchitectureTests`, `multiModule`, `versionCatalog`,
`buildSrc`, `buildLogic`, `conventionPlugins`, plus feature flags `compose`,
`hilt`, `room`, `datastore`, `ksp`, `kapt`, `ktor`, `retrofit`, `detekt`,
`konsist`, `androidLint`.

`inspect` is **read-only** by default (profile to stdout, no writes);
`--write` optionally writes `<project>/.aegl/project-profile.json`.

## 3. Module graph (`android-multimodule`)

Modules are parsed from `settings.gradle(.kts)` `include(...)`; per module the
adapter reads plugins (app/library) and declared project dependencies
(`project(":x")`).

```text
:app            → :feature:sample, :core:data, :core:domain
:feature:sample → :core:domain
:core:data      → :core:domain
:core:domain    → (nothing)
```

Rendered to `<project>/.aegl/android/module-graph.json`.

```text
app ──▶ feature:sample ──▶ core:domain
  └───▶ core:data ───────▶ core:domain
```

## 4. Architecture governance rules (Android Governance Model)

`.aegl/policy.json` is the **single source of truth** (the Android governance
model). The constitution, AI rules, Konsist rules, Detekt profile and the module
boundary rules are all *projections* of it — there is no parallel truth source.

Rules:

| Rule | Kind | Enforcement |
|------|------|-------------|
| A. Domain isolation: domain must not import `android.*` / `androidx.*` | deterministic | Konsist |
| B. Presentation boundary: UI/presentation must not use DAOs / databases / data sources | deterministic | Konsist (layer + DAO-name + Room) |
| C. Data boundary: data must not depend on presentation/UI | deterministic | Konsist layer rule |
| D. ViewModel boundary: `*ViewModel` must not hold `Activity`/`Fragment`/`View` (application `Context` allowed) | deterministic | Konsist |
| E. Room boundary: `@Entity` types must live in the data layer | deterministic (subset) | Konsist |
| F. Feature boundary: `:feature:*` must not depend on another `:feature:*` | deterministic | Gradle module-boundary + Konsist package rule |
| G. Compose boundary: `@Composable` must not access DAOs / databases / repositories | deterministic | Konsist |
| H. Module boundaries (see §5) | deterministic | Gradle task `aeglModuleBoundaryCheck` |

## 5. Deterministic vs semantic rules (honest split)

- **Deterministic (machine-verified):** all of the above. Konsist with
  `scopeFromExternalDirectories` performs real Kotlin source analysis — no
  `grep` / filename search is used as governance proof. The module graph is read
  from the **declared Gradle dependency graph** via the Gradle API.
- **Semantic (documented, NOT machine-verified):** "Room entities must not be
  exposed as UI state through the full data flow". Konsist cannot reliably follow
  an arbitrary entity→mapper→UI-state data flow, so this is recorded in
  `policy.json` (`android.rules.semantic`) and the architecture constitution as a
  semantic rule, and is **not** claimed as an executable check.

## 6. Konsist rules (executable, generated)

Generated into `.aegl/android/GeneratedAndroidArchitectureTest.kt` and injected
into a host module's unit-test source set:

1. `layer dependency policy must hold` — `Layer`s with `dependsOnNothing()` /
   `doesNotDependOn(setOf(...))` prohibitions derived from `mayDependOn`.
2. `domain must not depend on android`
3. `presentation must not access the data layer`
4. `view models must not reference ui framework types`
5. `composable functions must not access the data layer`
6. `feature modules must not depend on other feature modules`
7. `room entities must live in the data layer`

Konsist `0.17.3`. Note: `Layer.dependsOn(...)` is a *"must depend on"* assertion
(strict); prohibitions therefore use `doesNotDependOn(...)` / `dependsOnNothing()`.

## 8. Android Lint

`verify` really runs AGP Android Lint for every module
(`:app:lintDebug`, and `lintAnalyzeDebug`/`lintReportDebug`), not a plain Kotlin
compiler. `verify` reports the lint tasks it observed executing
(`gates.lint`, `lintTasksExecuted`).

## 9. Quality gate

`aegl verify <android-target>` runs `./.aegl/quality-gate.sh`, i.e.
`gradle --init-script .aegl/aegl-init.gradle --continue aeglQualityGate`, which
aggregates (per module):

```text
aeglModuleBoundaryCheck + detekt + testDebugUnitTest (Konsist + unit tests)
+ lintDebug (Android Lint) + assembleDebug (build validation)
```

`verify` returns a structured verdict: per-gate PASS/FAIL
(`moduleBoundary`/`detekt`/`lint`/`unitTests`/`build`), `architectureViolation`,
`moduleBoundaryViolation`, failing Konsist rules with file paths, Detekt findings,
Lint errors, and the executed lint tasks. Failures name the gate, the rule and
the file/module — not merely a Gradle exit code.

## 24. Known limitations

- **Literal `:core:domain → :app` is not representable** in a buildable Gradle
  graph (it forms a cycle with `:app → … → :core:domain`, and AGP forbids a
  library depending on an application module). The negative multi-module fixture
  therefore uses the equivalent, acyclic, real violation
  `:core:data → :feature:sample` (core/data → feature). The `domain-purity` and
  `no-depend-on-app` rules are implemented and enforced by the same task, but
  cannot be negatively exercised inside this particular module graph.
- The module-boundary check reads **declarable** configurations only
  (`api`, `implementation`, `compileOnly`, `compileOnlyApi`, `runtimeOnly`,
  `debugImplementation`, `releaseImplementation`); AGP's `*Classpath`
  configurations inject self/transitive edges and are intentionally ignored.
  Test-scope project dependencies are out of scope.
- The Konsist rule is injected into a single **host module** (first application
  module, else first library module) and scans every module's
  `src/main/kotlin|java` through absolute source dirs; module additions after
  `attach` are picked up automatically, but non-conventional source layouts
  (custom `sourceSets`) are not.
- The Android governance model uses convention-based role/layer heuristics;
  refine `.aegl/policy.json` for projects with unusual module semantics.
- `Room` entities must live in the data layer is the machine-checkable subset;
  the full entity→UI-state data flow is a documented semantic rule.
- `verify` downloads AGP/Konsist/Detekt from Google/Maven Central on first use.
- Only `android` and `kotlin` are implemented; `java`, `python`, `typescript`
  remain honest `implemented: false` descriptors.
- Windows bootstrap remains unverified.
